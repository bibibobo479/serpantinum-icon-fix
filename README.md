# Serpantinum Icon Fix

Исправление фиолетово-чёрных клетчатых иконок приложений в [Serpantinum](https://github.com/ilyamiro/serpantinum).

Утилита для **любого пользователя с совместимой установкой Serpantinum**: пути определяются автоматически, имя пользователя не зашито в код. Каждый запускает её в своём Linux-сеансе, **без `sudo`**. Это независимый проект, не официальный компонент Serpantinum.

[English documentation](docs/README.en.md)

## Запуск

Нужны Linux, Python **3.10+** и установленный Serpantinum. Для окна нужен Tk; терминальный режим работает на стандартной библиотеке Python. Исправление работает без интернета.

```bash
git clone https://github.com/bibibobo479/serpantinum-icon-fix.git
cd serpantinum-icon-fix
./run.sh
```

При наличии графической среды откроется окно и **автоматически выполнит исправление**. В окне доступны проверка, повторное исправление, откат и отдельная кнопка перезапуска Serpantinum. Приложения при перезапуске оболочки остаются открытыми.

Для работы без окна:

```bash
./run.sh --check               # Только диагностика, без записи файлов
./run.sh --apply               # Исправить и создать резервную копию
./run.sh --apply --restart     # Исправить и перезапустить оболочку
./run.sh --restore             # Отменить последнее исправление
```

Если окно недоступно, установите пакет Tk из репозитория своего дистрибутива: `tk` в Arch, `python3-tk` в Debian/Ubuntu, `python3-tkinter` в Fedora. Tk использует X11/XWayland; в сеансе только с Wayland используйте `--apply`.

## Установка в меню приложений

```bash
python3 install.py
```

Появится **Serpantinum Icon Fix**. Также можно запускать `~/.local/bin/serpantinum-icon-fix`. На системах с пользовательским systemd установщик также включает автоматическую проверку совместимости после обновлений.

## Устойчивость к обновлениям (1.1.0)

Компоненты иконок теперь хранятся отдельно: `$XDG_DATA_HOME/serpantinum-icon-fix/qml` (обычно `~/.local/share/serpantinum-icon-fix/qml`). Панель импортирует их явно через `IconFix`. Перезапись штатного `reusables/qmldir` больше не удаляет регистрацию нужного типа. Старые исправленные компоненты мигрируют при `--apply`; штатный `qmldir` не изменяется.

`python3 install.py` устанавливает и включает пользовательский `serpantinum-icon-fix.timer`. Примерно каждые 15–20 секунд он проверяет установку; перед ремонтом ждёт не менее 20 секунд без изменений QML-файлов. После полного обновления известные участки кода исправляются повторно с резервной копией. Неизвестный код новых версий пропускается. Таймер **не запускает и не перезапускает Serpantinum**, поэтому не создаёт вторую панель. Если обновление остановилось посреди копирования, стабильность файлов не гарантирует завершённую установку: нужно закончить штатное обновление.

Проверка и отключение:

```bash
systemctl --user status serpantinum-icon-fix.timer
journalctl --user -u serpantinum-icon-fix.service
systemctl --user disable --now serpantinum-icon-fix.timer
```

Перед намеренным откатом `--restore` отключите таймер, иначе он применит исправление снова. Без systemd или при нестандартной установке используйте `--apply` после обновлений вручную. Полная замена upstream-кода может временно вернуть обычные иконки до следующей проверки; совместимость с произвольными будущими изменениями не гарантируется.

## Что исправляет

- Восстанавливает отсутствующий или повреждённый `hicolor/index.theme` в пользовательском каталоге. Существующий исправный индекс не заменяется. Самих картинок программа не скачивает.
- Сохраняет рабочую тему, явно выбранную в `Shell.qml`. Если она не задана или недоступна, выбирает установленную тему: Papirus, Papirus-Dark, Breeze, Adwaita, затем hicolor.
- Исправляет известный участок кода меню и трёх компонентов дока: проверяет существование иконки, пробует имя без расширения, показывает штатный запасной значок при отсутствии картинки.
- При ошибке загрузки перебирает альтернативные файлы из тем, XDG, Flatpak и pixmaps; учитывает desktop ID и StartupWMClass.
- Резервный каталог обновляется при старте оболочки и раз в час. Python-процесс завершается после сканирования.
- Сохраняет оригинальные файлы, контрольные суммы и права доступа. Повторный запуск не дублирует исправления.

Qt кэширует темы иконок, поэтому после первого ремонта нужен **полный перезапуск оболочки**, а не только перечитывание QML. Для стандартной установки используйте кнопку в окне или `--restart`. Если оболочкой управляет другой сервис, перезапустите её привычным способом либо выйдите из сеанса и войдите снова.

## Нестандартная установка

```bash
./run.sh --check --shell /path/to/serpantinum/src/quickshell
./run.sh --apply --shell /path/to/serpantinum/src/quickshell --theme Papirus-Dark
./run.sh --check --json
```

Учитываются `XDG_DATA_HOME`, `XDG_CONFIG_HOME`, `XDG_STATE_HOME`, `XDG_DATA_DIRS`, `SERPANTINUM_DIR` и путь работающей оболочки. Можно передать путь к `Shell.qml`. При нескольких установках выберите нужную через `--shell`.

## Совместимость и ограничения

- QML-исправления проверены на **Serpantinum 2.3.0 (a62f825) и 2.5.0 (01f7c4d)**. Другие версии поддерживаются только при совпадении известных участков кода. Неизвестные компоненты пропускаются с сообщением; ремонт темы может всё равно помочь.
- Системные каталоги и Nix store не переписываются с повышенными правами. Компоненты установки без права записи пропускаются. Для NixOS настройте тему и патч в своей конфигурации либо используйте доступную для записи пользовательскую копию.
- Утилита не восстанавливает удалённые изображения, не исправляет произвольные ошибки `.desktop`/классов окон и не гарантирует исправление всех значков системного трея.
- Обновление Serpantinum может заменить QML-файлы. В таком случае запустите утилиту снова: она проверит актуальный код.
- Автоперезапуск поддерживает одну работающую установку под `serpantinumd`. Нестандартные менеджеры сеанса нужно перезапускать отдельно.

## Резервные копии и откат

Копии находятся в `${XDG_STATE_HOME:-~/.local/state}/serpantinum-icon-fix/backups/`. Команда `--restore` отменяет последнее ещё не отменённое исправление. Если файлы после ремонта изменил пользователь или обновление, откат останавливается **до записи**, чтобы не потерять новые изменения. Оригиналы остаются в папке копии для ручного сравнения.

Коды завершения: `0` — выполнено, `1` — ошибка, `2` — выполнено частично или есть ограничения. `--check` ничего не исправляет и не создаёт резервных копий.

## Проверка проекта

```bash
python3 -m unittest discover -s tests -v
```

Тесты проверяют отсутствующие и повреждённые индексы, XDG-пути, повторный запуск, сохранение темы, неизвестные версии QML, симлинки, откат, конфликт с новыми изменениями и ошибку записи. [Подробности проверки](docs/VALIDATION.md).
